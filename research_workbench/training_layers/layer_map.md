# 训练层级图

当前研究训练体系先按“**对象层 -> 任务层 -> 模型层 -> 评价层**”组织。

```text
研究目标
└── 面向 Agent 运维与项目理解的模型训练
    ├── 对象层
    │   ├── 代码结构
    │   ├── 项目文档
    │   ├── 运行状态
    │   ├── Agent 事件
    │   └── 证据链
    │
    ├── 任务层
    │   ├── 项目理解
    │   ├── 证据定位
    │   ├── 证据链重建
    │   ├── 工具/动作判断
    │   ├── 状态诊断
    │   └── 变更理解
    │
    ├── 模型层
    │   ├── baseline
    │   ├── instruction / SFT
    │   ├── encoder-like modules         # 预留
    │   ├── fusion / attention modules   # 预留
    │   └── future variants              # 预留
    │
    └── 评价层
        ├── 项目理解
        ├── 证据忠实
        ├── 运维行为
        ├── 泛化能力
        └── 训练代价
```

## 1. 对象层

对象层回答的是：**模型到底要理解什么。**

| 对象 | 含义 |
| --- | --- |
| 代码结构 | 文件、模块、依赖、入口、测试 |
| 项目文档 | README、设计说明、接口契约、方案备份 |
| 运行状态 | 任务状态、训练状态、错误、资源占用 |
| Agent 事件 | 工具调用、决策、失败、修复、日志 |
| 证据链 | 从结论回到代码、文档、日志、manifest 的可追踪路径 |

## 2. 任务层

任务层回答的是：**模型需要学会做什么。**

| 任务族 | 示例 |
| --- | --- |
| 项目理解 | 这个项目的技术栈是什么、入口在哪、模块如何协作 |
| 证据定位 | 给出结论所依赖的文件、片段、日志或 manifest |
| 证据链重建 | 将多个证据片段组织成完整推理链 |
| 工具/动作判断 | 当前应该查看资源、训练、评测还是结束 |
| 状态诊断 | 根据日志、状态和事件判断失败来源 |
| 变更理解 | 某次改动会影响哪些模块、测试或训练样本 |

## 3. 模型层

模型层先保留普通、主流、可解释的结构：

| 层级 | 作用 |
| --- | --- |
| baseline | 不加结构创新，只做基座对照 |
| instruction / SFT | 学项目问答、证据回答、协议行为 |
| reserved encoder modules | 为后续项目编码、证据编码预留 |
| reserved fusion modules | 为后续 cross-attention / 融合创新预留 |

这里故意不提前替未来创新定型。  
工作台现在只保证未来新增模块能够被挂载、登记、比较和评价。

## 4. 评价层

评价层回答的是：**模型是否真的学会了项目理解与证据理解，而不是只记住答案。**

评价至少覆盖：

1. 结论是否正确；
2. 引用的证据是否正确；
3. 证据链是否完整；
4. 面对新项目时是否仍然有效；
5. 训练代价是否可接受。
