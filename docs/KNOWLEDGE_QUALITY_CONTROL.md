# Knowledge Quality Control Framework

本文档给出面向本项目的论文级知识资产质量控制体系。其目标不是单纯增加若干经验规则，而是在知识采集、切片、卡片生成、训练样本导出和知识库发布的全过程中，建立一套**多粒度、可解释、可审计、可复现实验验证**的质量管理方法。

当前项目已经具备仓库级门禁 v1：

- `agent/evaluation/knowledge.py`：对单个学习仓库进行基础质量评估；
- `knowledge_quality_report.json`：记录质量评分；
- `knowledge_promotion.json`：记录晋级和拒绝原因；
- 学习链路只将晋级资产写入 `knowledge_cards.json`、`vector_index.jsonl` 和 `training_examples.jsonl`；
- 训练准备链会再次读取晋级清单，阻止未晋级资产绕过门禁进入微调数据集。

论文标准版的下一阶段，应在此基础上扩展为五层质量控制模型。

---

## 1. 设计目标

### 1.1 研究目标

知识增强与训练数据准备并不是“数据越多越好”。如果直接将低质量仓库、噪声切片、无来源知识卡和弱约束训练样本写入知识库，会造成以下问题：

1. 检索阶段返回与任务无关或不可追溯的内容；
2. 生成阶段引入事实错误和引用漂移；
3. 训练阶段将低质量知识继续蒸馏到备用本地模型中；
4. 系统难以说明“为什么相信这条知识”。

因此，本体系的目标是：

- 在资产进入知识库前完成质量评估和门禁；
- 在不同粒度上分别度量质量，而不是用单一分数替代全部判断；
- 将“可复用”“可追溯”“可训练”分开评价；
- 为论文中的系统设计、实验评价和创新点提供可量化支撑。

### 1.2 适用对象

| 层级 | 资产对象 | 主要问题 |
|---|---|---|
| L1 | 数据源 / 仓库 | 值不值得学 |
| L2 | 知识切片 | 适不适合检索 |
| L3 | 知识卡 | 可信不可信 |
| L4 | 训练样本 | 能不能用于本地模型二次训练 |
| L5 | 知识库整体 | 长期可不可用 |

## 2. 总体质量模型

### 2.1 多粒度评分思想

设某一层资产的质量指标集合为：

```text
M = {m1, m2, ..., mn}
```

每个指标对应标准化得分：

```text
si ∈ [0, 10]
```

则该层资产的综合质量分定义为：

```text
Q_layer = Σ(wi · si) / Σ(wi)
```

其中：

- `wi` 表示第 `i` 个指标的权重；
- `si` 表示第 `i` 个指标的归一化得分；
- `Q_layer` 取值范围为 `[0, 10]`。

五个层级分别记为：

```text
Q_repo, Q_slice, Q_card, Q_sample, Q_store
```

系统整体知识质量可表示为：

```text
Q_total = αQ_repo + βQ_slice + γQ_card + δQ_sample + εQ_store
```

并满足：

```text
α + β + γ + δ + ε = 1
```

建议初始权重：

| 层级 | 权重 |
|---|---:|
| 仓库级 `Q_repo` | 0.20 |
| 切片级 `Q_slice` | 0.20 |
| 卡片级 `Q_card` | 0.25 |
| 样本级 `Q_sample` | 0.20 |
| 整库级 `Q_store` | 0.15 |

原因是本项目的核心不是“仓库收得多”，而是“最终进入 RAG 与训练链的知识是否可信”，因此知识卡与训练样本需要更高权重。

### 2.2 双门禁机制

单一总分不足以表达风险。论文级质量控制应采用“**硬约束 + 软评分**”两级机制。

#### 硬约束

一旦命中，直接拒绝晋级：

- 无法定位来源；
- 疑似密钥、隐私数据或许可证不满足要求；
- 引用路径全部失效；
- 沙箱检查失败；
- 样本缺少必要输入或输出；
- 重复率超过设定上限；
- 训练样本存在明显泄漏或伪造证据。

#### 软评分

未触发硬拒绝时，再计算综合分：

- `Q >= 8.0`：优秀，可优先晋级；
- `6.5 <= Q < 8.0`：可用，可进入正式资产池；
- `4.0 <= Q < 6.5`：观察，进入候选区或待修复区；
- `Q < 4.0`：风险，不建议进入生产知识库。

这种设计的意义在于：  
**硬约束处理不可接受风险，软评分处理质量优劣差异。**

## 3. 五层质量指标体系

### 3.1 L1 数据源 / 仓库质量

### 目标

判断仓库是否具备“可学习性”和“可复用性”。

### 指标

| 指标 | 含义 | 建议计算方式 |
|---|---|---|
| 文档完整度 | README 与关键章节是否齐全 | install / usage / test 等章节覆盖率 |
| 结构完备度 | 是否存在入口、测试、依赖文件 | entrypoints、tests、package files 覆盖 |
| 可运行性 | 基础静态检查是否通过 | sandbox / compile / size check |
| 来源合法性 | 是否具有可接受许可证 | SPDX allowlist |
| 项目活跃度 | 是否有维护信号 | 更新时间、提交活跃度、star 仅作辅助 |
| 风险检测 | 是否存在明显敏感信息或危险文件 | secret scan / ignored paths |

### 建议公式

```text
Q_repo =
  0.20·D_doc +
  0.20·D_structure +
  0.20·D_runtime +
  0.15·D_license +
  0.10·D_freshness +
  0.15·D_risk
```

其中：

- `D_doc`：文档完整度；
- `D_structure`：结构完备度；
- `D_runtime`：可运行性；
- `D_license`：许可证合规性；
- `D_freshness`：活跃度或新鲜度；
- `D_risk`：安全风险得分。

### 硬门禁

- README 缺失；
- 许可证不满足允许范围；
- 沙箱失败；
- 检测到敏感信息；
- 完全没有可切片代码。

---

### 3.2 L2 知识切片质量

### 目标

判断“切出来的片段”是否适合后续检索、引用和聚合。

### 指标

| 指标 | 含义 | 建议计算方式 |
|---|---|---|
| 长度适配度 | 过短信息不足，过长不利于召回 | token 区间命中率 |
| 信息密度 | 是否包含有意义标识符、结构、语义 | 非停用 token 比例、函数/类标记 |
| 可定位性 | 是否保留文件、行号、语言信息 | path / line / language 完整率 |
| 重复度 | 是否与其他切片高度相似 | simhash / minhash / embedding similarity |
| 噪声率 | 是否主要由空白、生成代码、锁文件等构成 | 规则过滤比例 |
| 结构覆盖度 | 是否覆盖关键入口、接口、测试和配置 | 关键路径召回覆盖 |

### 建议公式

```text
Q_slice =
  0.20·S_length +
  0.20·S_density +
  0.20·S_trace +
  0.20·S_dedup +
  0.10·S_noise +
  0.10·S_coverage
```

### 硬门禁

- 无路径或行号；
- 空切片；
- 重复率超过阈值；
- 命中已知噪声文件；
- 超出最大长度且无法自动重切。

---

### 3.3 L3 知识卡质量

### 目标

判断摘要性知识是否“可相信、可回溯、可复用”。

### 指标

| 指标 | 含义 | 建议计算方式 |
|---|---|---|
| 引用覆盖率 | 有来源路径的知识卡比例 | `带引用卡片数 / 总卡片数` |
| 引用有效率 | 引用路径能否在仓库中找到 | `有效引用数 / 总引用数` |
| 事实一致性 | 卡片摘要是否能被来源支撑 | 摘要句与证据片段语义支持率 |
| 完整性 | 是否包含标题、摘要、标签、问题、来源 | 字段完整率 |
| 冗余度 | 多张卡是否表达同一事实 | 卡片间相似度 |
| 可问答性 | 卡片是否能支持自然问题回答 | question-answer support rate |

### 建议公式

```text
Q_card =
  0.25·C_citation_coverage +
  0.20·C_citation_validity +
  0.25·C_faithfulness +
  0.10·C_completeness +
  0.10·C_novelty +
  0.10·C_qa_support
```

### 硬门禁

- 无引用；
- 引用全失效；
- 摘要与证据矛盾；
- 与已有卡片高度重复且无新增信息。

---

### 3.4 L4 训练样本质量

### 目标

判断样本是否适合用于本地备用模型的二次训练。

### 指标

| 指标 | 含义 | 建议计算方式 |
|---|---|---|
| 指令完整性 | instruction / input / output 是否齐全 | 字段完整率 |
| 回答忠实度 | 输出是否受证据支持 | citation-grounded support |
| 引用保留率 | 训练样本是否保留来源 | citations coverage |
| 任务多样性 | 是否覆盖 QA、解释、方案复用等任务 | task entropy / task count |
| 去重质量 | 是否存在模板重复和近重复 | exact + semantic dedupe |
| 安全合规性 | 是否含密钥、隐私、许可证风险 | governance scan |
| 训练价值 | 是否具有足够信息量和监督信号 | 长度、复杂度、结构化程度 |

### 建议公式

```text
Q_sample =
  0.15·T_completeness +
  0.25·T_faithfulness +
  0.15·T_citation +
  0.10·T_diversity +
  0.15·T_dedup +
  0.10·T_governance +
  0.10·T_supervision
```

### 硬门禁

- instruction 或 output 缺失；
- 疑似泄漏敏感信息；
- 样本无证据且声称基于证据；
- 与已有样本近重复；
- 输出过短、过长或明显无效。

---

### 3.5 L5 知识库整体质量

### 目标

判断一批已晋级资产组成的知识库是否具备长期使用价值。

### 指标

| 指标 | 含义 | 建议计算方式 |
|---|---|---|
| 覆盖度 | 是否覆盖目标任务需要的主题 | 主题覆盖率 / 标签覆盖 |
| 冗余率 | 整库近重复程度 | duplicate rate |
| 新鲜度 | 资产更新时间是否合理 | freshness score |
| 检索质量 | 是否能召回正确证据 | Recall@k、MRR、nDCG |
| 回答忠实度 | RAG 输出是否基于证据 | grounded answer rate |
| 可训练性 | 进入训练链后保留的高质量样本比例 | accepted sample rate |

### 建议公式

```text
Q_store =
  0.15·K_coverage +
  0.15·K_redundancy +
  0.10·K_freshness +
  0.25·K_retrieval +
  0.20·K_groundedness +
  0.15·K_trainability
```

### 硬门禁

- 整库无可检索证据；
- 高风险资产占比超过阈值；
- 关键主题覆盖严重不足；
- RAG 回答在基准集上显著退化。

## 4. 质量控制流程设计

```text
GitHub / Local Repo / Web
  -> L1 数据源评估
     -> 不通过：进入 rejected_assets
     -> 通过：进入 parser / slicer
  -> L2 切片质量评估
     -> 去噪 / 重切 / 去重
  -> L3 知识卡质量评估
     -> 事实一致性检查
     -> 引用覆盖检查
  -> 候选知识资产池
  -> L4 训练样本质量评估
     -> governance scan
     -> dedupe / faithfulness / diversity
  -> L5 整库质量聚合
     -> 正式知识库
     -> 训练数据集
     -> 质量报告 / 晋级清单 / 审计日志
```

### 4.1 资产生命周期

建议将资产状态统一为：

| 状态 | 含义 |
|---|---|
| `raw` | 原始采集，尚未评估 |
| `candidate` | 通过基础校验，等待多粒度评估 |
| `watch` | 有价值但存在缺陷，暂不进入正式库 |
| `promoted` | 通过门禁，可进入正式知识库 |
| `rejected` | 不满足硬约束 |
| `deprecated` | 曾可用，但因过期、冲突或质量退化被下线 |

### 4.2 设计原则

1. **先证据，后总结**：知识卡不得脱离来源生成；
2. **先门禁，后训练**：训练样本必须继承知识资产晋级状态；
3. **先局部，后整体**：仓库合格不等于整库一定健康；
4. **先可解释，后自动化**：每次拒绝都要给出原因；
5. **先保守，后放宽**：备用模型训练优先保障质量，而不是追求样本数量。

## 6. 实验设计

### 6.1 研究问题

建议在论文中围绕以下问题展开：

1. 多粒度质量控制能否提升知识资产整体质量？
2. 与无门禁、单层门禁相比，多层门禁是否能改善 RAG 检索与回答表现？
3. 质量控制是否会提升备用本地模型训练数据的可用性？
4. 各质量层级中，哪一层对最终效果贡献最大？

### 6.2 对照组

| 组别 | 设置 |
|---|---|
| G0 | 无质量控制：所有资产直接入库 |
| G1 | 仅仓库级门禁：使用当前 v1 |
| G2 | 仓库级 + 切片级 |
| G3 | 仓库级 + 切片级 + 卡片级 |
| G4 | 完整多粒度体系：L1-L5 |

### 6.3 数据集建议

为了保证论文可复现，建议准备三类集合：

1. **原始仓库集合**
   - 本地样例项目；
   - GitHub 筛选项目；
   - 高质量、一般质量、低质量仓库各占一定比例。

2. **问答评测集合**
   - 项目运行方式；
   - 架构定位；
   - 接口功能；
   - 文件路径；
   - 依赖与测试。

3. **训练样本抽检集合**
   - 人工标注样本是否可训练；
   - 标注引用是否充分；
   - 标注回答是否与证据一致。

### 6.4 评价指标

### 资产质量指标

| 指标 | 说明 |
|---|---|
| 晋级率 | `promoted / total` |
| 引用覆盖率 | 有引用知识卡占比 |
| 引用有效率 | 可解析来源引用占比 |
| 重复率 | 近重复资产占比 |
| 高风险资产率 | 触发硬门禁资产占比 |
| 样本通过率 | 最终可进入训练集的样本比例 |

### RAG 指标

| 指标 | 说明 |
|---|---|
| Recall@k | 正确证据是否被召回 |
| MRR | 正确证据排名 |
| nDCG | 多证据排序质量 |
| Grounded Answer Rate | 回答是否由证据支撑 |
| Citation Accuracy | 引用是否正确 |

### 训练数据指标

| 指标 | 说明 |
|---|---|
| Citation Retention | 训练样本保留引用比例 |
| Accepted Sample Rate | 通过质量与治理门禁的样本比例 |
| Duplicate Reduction | 去重前后样本下降比例 |
| Task Diversity | 任务类型丰富度 |
| Manual Acceptance Rate | 人工抽检通过率 |

### 6.5 消融实验

建议至少设计以下消融：

| 实验 | 去掉的能力 | 观察目标 |
|---|---|---|
| A1 | 去掉切片去重 | 重复率、召回质量变化 |
| A2 | 去掉知识卡引用检查 | 引用覆盖率、回答忠实度变化 |
| A3 | 去掉样本治理 | 训练样本通过率、风险样本率变化 |
| A4 | 去掉整库聚合评估 | 长期质量退化是否更难被发现 |

### 6.6 预期结果表达方式

论文中建议使用：

1. **晋级漏斗图**：展示每一层保留下来的资产数量；
2. **质量雷达图**：展示各组别在不同维度上的差异；
3. **消融实验表**：展示移除某能力后的指标变化；
4. **前后对比表**：展示 G0 与 G4 在 RAG、样本、整库指标上的差异；
5. **案例分析**：列出一个被拒绝资产和一个被晋级资产，解释判定原因。

## 7. 可直接写入论文的章节建议

### 7.1 第 4 章总体设计可写内容

可将该体系表述为：

## 9. 一句话总结

本体系的核心不是“过滤差数据”，而是将知识资产从采集到训练的全过程转化为一个**有标准、有证据、有门禁、有实验验证**的质量闭环。
